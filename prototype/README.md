# 妆舟流程工作台 — 桌面契约原型

## 当前范围

直接修改现有本地项目，以已收到的 V4 MD 为数据契约、HTML 为画布视觉参考。仍使用原 `index.html` 入口，不新增站点，不部署。移动端不在本轮范围。

本轮以共享仓库 `main` 的 `23ef629beab623674a07cad4e302bc481a78abf0` 为基点，在 `codex/desktop-contract-v0.1` 分支整合此前本地实现。保留基线业务 `app.js` 与 `styles.css`，只在原页面入口挂接桌面契约工作台。这不是 ChatGPT Sites 原站源码导出或部署。

版本化交付说明与测试证据见 `../evidence/desktop-contract-v0.1/`。早期本地包、分块和其中哈希属于历史交付，不作为当前共享分支的文件身份。

## 使用路径

1. 首屏只显示画布和一个主操作“确认流程目标”。填写目标后，进入四个业务阶段的拆解确认；不会自动覆盖已有步骤。
2. 点击“确认拆解，检查缺项”，在具体问题旁点“去这一步补充”，直接打开对应步骤。错误未解决不能推进执行。
3. 点击画布卡片，才打开右侧浮动设置层；先看业务目的和处理说明，模型引用、五段、端口和技术字段按需展开。点关闭回到画布。
4. 左侧四类入口按需弹出：输入、AI 处理、人、输出。先点输出端口，再点目标输入端口连接；系统口只可改名，自定义口可增删改。
5. 底部工具栏提供流程对话、模板、检查、缩放、整理布局、撤销和保存。整理布局可撤销，不修改配置或连接；载入旧草案不会擅自重排人工位置。
6. 有错误的草案仍可保存到本浏览器。合格的单卡可保存为本地模板，插入副本不会带入旧连线或运行状态。

这是离线配置和结构检查，不是实际运行，也不是模型驱动的自然语言生成。流程对话目前只将已确认文字写入当前步骤说明或全流程目标。没有真实模型、媒体、审批、付费、发布、业务写回能力。

## 架构与边界

- `relay-model.js`：9 类节点、四类端口、校验、端口操作、模板和快照纯函数。
- `relay-ui.js` / `relay-ui.css`：同一页面的桌面画布、设置、连接、模板、检查和本地保存。
- `app.js` / `workbench.js`：保留原 13 业务原子及旧业务层；入口转交给契约工作台。旧业务回归不是新版浏览器验证。
- 原业务五段保存在 `params.businessContract`，不递归成五个技术节点；AI 三段提示词不等于业务五段。
- 10 ai/3 sign 只是编辑结构投影。精确产物、Human 审批、六镜依赖、确定性工具和媒体动作未完成执行适配，始终展示迁移提示。
- 旧保存键不覆盖；支持本地 WorkbenchDraft 与共享基线 PrototypeDraft 的校验和完整快照保留，已有人工说明载入。旧自定义端口、依赖、停用状态、模型和能力需重新映射，不伪装无损迁移；旧报告与演示结果不充当当前运行证据。
- V4 通用端口允许扇入/扇出；六镜数量、唯一 shotId 是另一层业务约束。
- `fields-1.1.md` 完整数值上限、线上能力与授权未核验；填写不代表权限通过。

## 运行政策

保存、模板、编辑和检查均只操作本地草案。真实运行按钮禁用，CSP 保持 `connect-src 'none'`。检查不生成审批、不派生已批准素材包、不执行下游。平台执行 `not_run`，A2 `blocked`。

冻结的 v1.1 handoff 与旧分块保持原样，不能与本轮变更混用哈希。
